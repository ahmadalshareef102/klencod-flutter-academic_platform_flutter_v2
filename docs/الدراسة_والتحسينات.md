# دراسة المنصة الأكاديمية الرقمية والتحسينات المقترحة

## أولاً: نتيجة الدراسة (الوضع الحالي)
**نقاط القوة:** مصادقة حقيقية عبر Supabase، أربعة أدوار (طالب، مدرس، رئيس قسم، إدارة)، سياسات RLS على كل الجداول، إنشاء الحسابات عبر Edge Function محمية، واجهة عربية RTL بخط Cairo، وبناء APK آلي عبر GitHub Actions.

**الملاحظات التقنية:**
1. الكود كله في ملف واحد (`main.dart` ≈ 2650 سطراً) — يصعب صيانته؛ بدأنا بفصل الدرجات في `grades.dart` ويُنصح بإكمال التقسيم (شاشات / نماذج / خدمات).
2. لا يوجد إشعار خارج التطبيق (Push) — الإشعارات داخل التطبيق فقط.
3. الملفات تُرفق كروابط فقط، لا رفع مباشر (Supabase Storage).
4. لا تصدير تقارير (PDF/Excel) ولا كشف درجات رسمي.
5. لا استعادة كلمة المرور ولا تغييرها من داخل التطبيق.
6. لا وضع داكن، ولا بحث عام.
7. مفتاح Supabase العام داخل الكود (مقبول لأنه publishable، لكن الأفضل تمريره بـ dart-define كما في الـ workflow).

## ثانياً: ما أُضيف في هذه النسخة
- **الخلفية:** شعار جامعة الحديدة · كلية التربية زبيد كعلامة مائية هادئة على كل الشاشات، والشعار الكامل في شاشة الدخول وشريط الرئيسية.
- **رصد الدرجات (المدرس):** أعمال السنة + النصفي + النهائي لكل طالب، مجموع وتقدير فوري، بحث، وتحقق من الحد الأعلى.
- **التحكم بالنتائج (الإدارة ورئيس القسم):** فتح/إغلاق الرصد لكل مقرر، تعديل الدرجات العظمى، مراجعة الكشف مع المتوسط ونسبة النجاح، اعتماد ونشر النتائج، إلغاء النشر، إعادة الإرسال.
- **إرسال النتيجة لكل طالب:** عند النشر يصل كل طالب إشعار خاص بتفاصيل درجاته وتقديره، ويرى «نتائج المقررات» ببطاقات ومعدل عام.
- **الحماية:** كل ذلك مفروض في قاعدة البيانات (RLS + مشغّل تحقق + دالة نشر للإدارة فقط)، فلا يستطيع الطالب رؤية نتيجة غير منشورة ولا المدرس التعديل بعد الإغلاق.

## ثالثاً: اقتراحات مرتبة حسب الأولوية
1. **إشعارات Push** عبر Firebase Cloud Messaging (تصل النتيجة والإعلان والتكليف حتى والتطبيق مغلق).
2. **تصدير كشف الدرجات PDF/Excel** وشهادة نتيجة للطالب بشعار الجامعة.
3. **رفع الملفات** (محاضرات، تسليم تكليفات) عبر Supabase Storage بدل الروابط.
4. **استعادة كلمة المرور** وتغييرها، وإجبار تغيير كلمة المرور عند أول دخول.
5. **رصد جماعي**: استيراد الدرجات من Excel، وعدة اختبارات/مفردات بدل ثلاثة حقول ثابتة.
6. **سجل تدقيق** (من عدّل أي درجة ومتى) وإشعار المدرس عند تعديل الإدارة.
7. **اعتراض على الدرجة** من الطالب خلال مدة تحددها الإدارة.
8. **مؤشرات للقسم**: الطلاب المعرضون للحرمان بسبب الغياب، مقارنة بين المقررات.
9. **الوضع الداكن** وتكبير الخط، ثم **تقويم أكاديمي** وجدول المحاضرات.
10. **اختبارات آلية** (`flutter test`) للشاشات الجديدة وتقسيم الكود.

## رابعاً: خطوات التفعيل
1. نفّذ `supabase/grades_patch.sql` في SQL Editor.
2. ارفع المشروع إلى GitHub كالمعتاد ليُبنى APK.
3. جرّب بحسابات الأدوار الأربعة: مدرس يرصد ← إدارة تنشر ← طالب يستلم النتيجة.

> ملاحظة: التقدير المستخدم: ≥85 ممتاز، ≥75 جيد جداً، ≥65 جيد، ≥50 مقبول، وغير ذلك راسب. يمكن تعديله في `gradeLabel` (Dart) و`grade_label` (SQL).
